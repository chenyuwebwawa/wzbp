# 安装脚本说明（install.sh）

> 这是 [宝塔部署教程](宝塔部署教程.md) 的**自动化版本**。
> 教程是「手点宝塔面板」的 20 分钟流程，本脚本把它变成一条命令：**只需要填域名**。
>
> 不想让脚本动手？那就照教程一步步点。想省事 / 想批量装机，用本脚本。

---

## 1. 三种用法

### ① GitHub 一键（推荐给最终用户）

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/chenyuwebwawa/wzbp/main/install.sh) \
     --domain bp.example.com
```

> `chenyuwebwawa/wzbp` 换成真实仓库地址（也就是把项目传上去的那个仓库）。
> 这种方式脚本自身不在项目目录里，它会自动把项目装到 `/www/wwwroot/wzbp`；
> 但**项目文件得有个来源**，二选一：
> - `--repo https://github.com/<账号>/<仓库>.git`：脚本用 `git clone` 拉取（推荐）
> - `--tarball https://…/wzbp.tar.gz`：脚本下载 tar.gz 解压
>
> 两个都不给、目录里又没有项目文件时，脚本会**明确报错并告诉你三种修法**（不会瞎猜地址）。

### ② 先克隆再跑（最稳，推荐）

```bash
git clone https://github.com/<账号>/<仓库>.git wzbp
cd wzbp
sudo bash install.sh --domain bp.example.com
```

在项目目录里运行时，站点目录默认就是**当前项目目录**。

### ③ 本机预演（不改任何东西）

```bash
# 在 Windows 的 Git Bash / WSL / macOS 上都能跑，用来检查脚本会做什么
bash install.sh --dry-run --domain test.example.com
```

`--dry-run` 下**所有写操作都只打印**：不建目录、不写文件、不 chmod/chown、不连数据库、
不碰 Nginx、不装依赖、不发网络请求。适合先在开发机上看清楚流程，再上服务器执行。

## 2. 参数一览

| 参数 | 说明 | 默认 |
| --- | --- | --- |
| `--domain <域名>` | **唯一必填**。站点域名，也允许直接填 IP | — |
| `--port <端口>` | Node 服务端口（只监听 `127.0.0.1`） | `8787` |
| `--dir <路径>` | 站点目录 | 脚本所在的项目目录；不在项目目录里运行时为 `/www/wwwroot/wzbp` |
| `--db-name <库名>` | 数据库名（只允许字母/数字/下划线/`$`，与服务端白名单一致） | `wzbp` |
| `--db-user <用户名>` | 数据库用户 | `wzbp` |
| `--db-pass <密码>` | 数据库密码 | 自动生成 24 位随机强密码 |
| `--db-host <主机>` | 数据库主机 | `127.0.0.1` |
| `--db-port <端口>` | 数据库端口 | `3306` |
| `--db-root-user <用户>` | 建库用的管理员账号 | `root` |
| `--db-root-pass <密码>` | 管理员密码 | 先从宝塔配置里找，找不到就交互询问 |
| `--repo <git 地址>` | 远程模式下自动拉取项目（也可用环境变量 `WZBP_REPO`） | 空 |
| `--tarball <地址>` | 远程模式下用 tar.gz 包代替 git | 空 |
| `--service <方式>` | 常驻方式：`auto` / `bt` / `pm2` / `systemd` | `auto` |
| `--ssl-email <邮箱>` | 申请 Let's Encrypt 用的邮箱 | 空（用 `--register-unsafely-without-email`） |
| `--no-nginx` | 只装 Node 服务与数据库，不动 Nginx | 关 |
| `--no-ssl` | 不申请 HTTPS | 关（默认尝试，失败不阻断） |
| `--uninstall` | 卸载：停服务 + 删 Nginx 配置（**不删数据库**） | 关 |
| `--yes` / `-y` | 非交互确认（CI / 无人值守） | 关 |
| `--dry-run` | 只打印将要执行的操作 | 关 |
| `--verbose` / `-v` | 额外打印被调用命令的输出（排错用） | 关 |
| `--help` / `-h` | 中文帮助 | — |
| `--version` | 显示脚本版本 | — |

写法上 `--domain bp.example.com` 和 `--domain=bp.example.com` 都支持。

## 3. 八步流程（与教程逐条对应）

| 脚本步骤 | 做什么 | 对应教程 |
| --- | --- | --- |
| `[1/8]` 环境自检 | 必须 root；检测宝塔 `/www/server/panel`、Nginx、MySQL、Node 18+；缺 Node 会尝试自动装（宝塔 Node 管理器优先，装不上就非零退出并给出手动步骤）；最后打印安装计划并确认 | §2 |
| `[2/8]` 站点目录与项目文件 | 建/校验站点目录，检查 `index.html`、`overlay.html`、`data/`、`vendor/`、`server/`（教程强调最容易漏的两个目录），`chown -R www:www` + `chmod -R 755` | §3 |
| `[3/8]` 数据库 | `CREATE DATABASE IF NOT EXISTS`、建 `wzbp@localhost` 与 `wzbp@127.0.0.1` 两个用户、授权、同步密码。**不导 `schema.sql`**——表由服务第一次启动时自己建；重复执行时若库和用户已能用就整段跳过 | §4 |
| `[4/8]` `.env` | 写 `WZBP_PORT / WZBP_DB_HOST / WZBP_DB_PORT / WZBP_DB_USER / WZBP_DB_PASSWORD / WZBP_DB_NAME`，`chmod 600`，并确保 `.gitignore` 忽略 `.env` | §5 / §6 |
| `[5/8]` 依赖 | 在站点目录执行 `npm install --omit=dev`（只装 `mysql2`），装完校验 `node_modules/mysql2` 存在 | §5 |
| `[6/8]` 常驻服务 | 三选一：宝塔 Node 项目（检测到已登记时）/ pm2（已装时）/ systemd（`wzbp.service`）；并写 `.wzbp-install-state` 安装记录 | §6 |
| `[7/8]` Nginx | 写独立站点配置文件（宝塔惯例 `/www/server/panel/vhost/nginx/<域名>.conf`），含 SSE 关键配置；改动前备份，`nginx -t` 失败**自动回滚** | §7 |
| `[8/8]` HTTPS + 自检 | 有 `certbot` 就自动申请（失败不阻断），没有就打印宝塔面板一键申请的路径；然后 `curl 127.0.0.1:<端口>/api/health` 要求 `db:true`，打印访问地址、房间入口提示与下一步 | §8 / §9 |

任何一步失败都会打印：

```
✗ 安装失败：步骤 3/8 建数据库与数据库用户（…）
  原因：…
  怎么修：…
```

并以非零码退出。参数错误退出码 `2`，运行期失败退出码 `1`。

## 4. 脚本会改哪些文件（精确清单）

| 路径 | 什么时候写 | 回滚办法 |
| --- | --- | --- |
| `<站点目录>/.env` | 总是 | 删掉即可（里面的密码同时失效） |
| `<站点目录>/.wzbp-install-state` | 总是（第 6 步） | 删掉即可，卸载会退化为按环境推断 |
| `<站点目录>/.wzbp-pm2.json` | 仅 pm2 模式 | 删掉；`pm2 delete wzbp` |
| `<站点目录>/.gitignore` | 仅当它还没忽略 `.env` 时，追加一条 `.env` 规则（带一行注释） | 删掉追加的那几行 |
| `/www/server/nodejs/vhost/scripts/wzbp.sh` | 宝塔 Node 管理器存在时 | 删掉 |
| `/etc/systemd/system/wzbp.service` | 仅 systemd 模式 | `systemctl disable --now wzbp && rm 该文件 && systemctl daemon-reload` |
| `/www/server/panel/vhost/nginx/<域名>.conf`<br>（非宝塔环境为 `/etc/nginx/conf.d/wzbp-<域名>.conf`） | 第 7 步（除非 `--no-nginx`） | 覆盖前自动备份为 `<同名>.bak.<时间戳>`；`nginx -t` 失败会**自动**还原备份或删除新文件 |
| 站点目录属主/权限 | 第 2 步 | `chown -R root:root <目录>` 还原（若不需要 www 用户） |

**不会做**的事情：

- 不删数据库、不 DROP 表、不清数据（`--uninstall` 也不删，只会把删除命令打印出来）
- 不往 Nginx 主配置里塞东西，只写独立站点文件
- 不改 MySQL 配置、不动防火墙、不放行 8787 端口
- 不写 `schema.sql`（服务自己建表）
- 密码不落进任何会被 git 跟踪的文件

## 5. 环境变量是怎么注入服务的

`.env` 只是**唯一的密码落盘位置**，服务端 `server/config.js` 读的是进程环境变量，
所以三种常驻方式各自这样注入（脚本已自动处理）：

| 常驻方式 | 注入方式 |
| --- | --- |
| systemd | 单元里写 `EnvironmentFile=-<站点目录>/.env`，密码不进单元文件 |
| pm2 | `.wzbp-pm2.json` 里 `env_file` 指向 `.env`，并且启动前 `set -a; . ./.env; set +a`，两条保险 |
| 宝塔 Node 项目 | 启动脚本 `wzbp.sh` 里 `source .env` 后再 `exec node server/index.js`；**面板的环境变量列表不会自动读 `.env`**，需要你把 6 条照着填一遍（也可以直接用这个启动脚本） |

手动试跑（教程 §5 的方式，脚本里也打印了这条）：

```bash
cd <站点目录> && set -a && . ./.env && set +a && node server/index.js
```

## 6. 卸载与回滚

```bash
sudo bash install.sh --uninstall --domain bp.example.com
```

卸载做四件事：

1. 自检（root）
2. 停服务并移除常驻配置（systemd：`disable --now` + 删单元；pm2：`pm2 delete wzbp`；宝塔：`pkill` 进程并提示你在面板删项目）
3. 备份后删除 Nginx 站点配置，再 `nginx -t` + reload（如果删完反而报错，会把备份放回去）
4. 打印**不会自动删**的东西：数据库删除命令、站点目录、`.env`、`.wzbp-install-state`、Nginx 备份文件

想彻底恢复原样，按第 4 步打印的清单手工处理即可；Nginx 备份是
`<配置文件>.bak.<时间戳>`，改名回去再 `nginx -t && nginx -s reload` 就恢复了。

## 7. 常见问题（脚本角度）

**Q：脚本说「目录里没有项目文件」。**
三种修法：在项目目录里运行 / 加 `--repo <git 地址>` / 加 `--tarball <地址>`，或手动把项目文件放进 `--dir` 指定的目录。

**Q：宝塔 Node 项目那一步让我去面板点一次？**
宝塔面板没有稳定的命令行接口来登记 Node 项目，所以脚本的处理是：
检测到**已经登记**过 `wzbp` 项目 → 直接重启交给面板守护保活；
没登记 → 写好启动脚本 `wzbp.sh`，打印面板里要填的 6 行，然后要求你加一次再重跑
（若机器上有 pm2 或 systemd，脚本会自动改用它们常驻，不必手点）。
这一步是为了**不谎报成功**：没登记就是没登记。

**Q：`nginx -t` 失败？**
脚本会自动回滚到备份并保持 Nginx 可用的状态，然后打印 `nginx -t` 的真实输出。
按提示检查：Nginx 是否装了、站点根目录是否存在、配置目录是否可写。

**Q：`/api/health` 返回 `db:false`？**
说明 Node 起来了但连不上 MySQL。按 `[8/8]` 打印的三条排查（MySQL 是否运行、`.env` 里的账号密码、宝塔里该用户的权限是否「本地服务器」），也就是教程 §11 Q1。

**Q：不想用 Nginx / 不想开 HTTPS？**
`--no-nginx` / `--no-ssl`。`--no-nginx` 时脚本会把必须手工写进反代的 SSE 几行打印出来。

## 8. 验证状态（诚实说明）

**在本机（Windows + Git Bash 5.3）真正跑过的：**

- `bash -n install.sh` 语法检查通过
- `bash install.sh --help` 输出完整中文帮助，退出码 0
- `bash install.sh --dry-run --domain test.example.com` 完整跑完 8 步，退出码 0，**没有创建/修改任何文件**（`git status` 前后一致，未生成 `.env`、`.wzbp-install-state`，未创建 `/www`）
- 同一条 dry-run 跑两次输出**逐字节一致**（`diff` 无差异）——时间戳、随机密码在 dry-run 下都用占位符
- 缺 `--domain`、非法参数退出码 2；端口越界退出码 2；非法库名退出码 1
- `--no-nginx` / `--no-ssl` / IP 域名 / URL 形式域名（`http://BP.Example.com/a/b/` → `bp.example.com`）/ `--service pm2` / `--repo` 拉取分支 / `--uninstall` 的 dry-run 分支都跑过
- 密码含 `"` `$` `` ` `` `\` 时，`.env` 转义后 `source` 回来与原文**完全一致**（`sql_escape` / `env_escape` 直接调用脚本内真实函数验证）

**本机没有、因此没有验证的（上服务器后请按教程 §9 复核）：**

- 真实宝塔面板环境：面板是否识别脚本写的 vhost 配置、面板 Node 项目管理器是否读取 `wzbp.sh`、面板的 Node 项目登记路径（脚本只能做存在性探测）
- `nginx -t` 是否真的通过、`nginx -s reload` 是否真的生效、宝塔主配置是否 include 了 `vhost/nginx/*.conf`
- MySQL 是否真的建库建用户成功、`mysql_do` 的 SQL 在 MySQL 5.7 / 8.0 / MariaDB 上的差异（`CREATE USER IF NOT EXISTS`、`ALTER USER`）
- systemd 单元能否真的启动、`pm2` 是否接受 `env_file` 字段、服务是否真的常驻与开机自启
- `certbot --nginx` 是否能申请成功（多数宝塔环境没装 certbot，会走「面板申请」提示分支）
- 服务端在真实 MySQL 下 `/api/health` 是否返回 `db:true`

一句话：**脚本逻辑在本机验证过，真机行为必须上服务器复核**。

## 9. 安全提醒

1. `8787` **不要**对公网放行（Node 只监听 `127.0.0.1`，外网走 Nginx）。
2. `.env` 里是数据库密码：`chmod 600`、已被 `.gitignore` 忽略，别提交、别贴群里。
3. 数据库权限选「本地服务器」；脚本只在库不在本机时才额外授权 `%` 并会警告你。
4. 安装完把 HTTPS 打开并强制跳转（教程 §8）。
5. 定期备份数据库和站点目录（教程 §10）。
