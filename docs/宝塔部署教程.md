# 宝塔面板部署教程（Linux）

> 面向：把 **王者荣耀 BP 展示台** 部署到自己的服务器，让别人也能通过网址访问、
> 开房间一起做 BP、并把每局 BP 存下来随时回放。
>
> 环境：**宝塔 Linux 面板 7.x / 8.x + MySQL 5.7 或 8.0 + Node.js 18+ + Nginx**
>
> 全程约 20 分钟。命令可以用宝塔的「终端」，也可以用 SSH。

---

## ⚡ 懒人路线：一行命令

如果你已经装好宝塔面板和 MySQL（软件商店装一下就行），**只想赶紧跑起来**：

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/chenyuwebwawa/wzbp/main/install.sh) \
     --domain bp.example.com
```

把 `bp.example.com` 换成你的域名（没有域名也可以直接填服务器 IP）。
脚本会自动做完下面第 2~9 步的全部事情，并在最后告诉你访问地址。

- 想先看它会改哪些东西：加 `--dry-run`（**只打印、不改系统**）
- 参数说明、卸载回滚：**[安装脚本说明](安装脚本说明.md)**
- **想自己一步步来、或者想搞清楚每步在干什么 —— 继续往下看本文档。**

## 1. 部署前要理解的三件事

### 1.1 为什么必须用 Node 服务，不能只传静态文件

网站本身是纯静态的（`index.html` + `js/` + `data/`），双击就能跑。
但你要的三件事 —— **开房间、多人加入战队、把 BP 结果存下来并回放** —— 需要一个后端：

| 需求 | 靠什么实现 |
| --- | --- |
| 房间 / 战队席位 | Node 服务 + MySQL 存房间和成员 |
| 多人实时同步 | Node 服务推送 **SSE** 事件流（`/api/stream`） |
| BP 数据保存与还原 | MySQL 存每一手动作（谁、第几手、多久、选谁） |
| 随机征召 | 服务端洗牌生成顺序并存库 |

所以架构是：**Nginx 直接发静态文件，`/api/` 转给本机的 Node 服务。**

```
用户浏览器
   │  https://你的域名
   ▼
宝塔 Nginx ──┬── /            → 静态文件（网站根目录）
             └── /api/、/api/stream → 127.0.0.1:8787（Node 服务）→ MySQL
```

> **重要**：Node 服务只监听 `127.0.0.1`，不直接对外。外网一律走 Nginx，
> 这样 HTTPS、域名、防攻击都由 Nginx 处理，Node 只管业务。

### 1.2 一个容易踩的坑：`file://` 下联网功能不可用

浏览器**不允许**从 `file://` 打开的页面访问任何 http 服务（实测 Chrome 会直接拦截，
加 CORS 头也没用）。所以：

- 本机双击 `index.html` → 纯静态模式，BP、面板、截图全都好用，但**看不到「房间」入口**；
- 通过域名（`https://…`）访问 → 自动进入**联网模式**，出现「房间」「战绩」入口。

这是预期行为，不是 bug。

### 1.3 你需要准备什么

- 一台服务器（1 核 1G 就够，这是个很轻的服务）
- 宝塔面板已装好，并能登录
- 一个域名（没有也能用 IP 访问，但没法开 HTTPS）
- 项目的全部文件（就是你现在这个 `wzbp` 目录）

## 2. 第一步：装环境（Node + MySQL + Nginx）

登录宝塔面板 → 左侧【软件商店】→ 依次安装：

| 软件 | 装哪个 | 说明 |
| --- | --- | --- |
| **Nginx** | 1.24 或更高 | 宝塔一般默认已装 |
| **MySQL** | 5.7 或 8.0 | 只存文本数据，1G 内存选 5.7 更省 |
| **Node.js 版本管理器** | 搜「Node」 | 装 **18 LTS 或 20 LTS**（不要选 22+ 以外的奇数版） |

也可以用命令行装 Node（宝塔的 Node 管理器更省事，推荐用它）。

装完在【软件商店】里确认三个都是「运行中」。

> 内存只有 1G 的话，MySQL 8.0 可能吃紧。装完在 MySQL 设置里把
> `innodb_buffer_pool_size` 调到 `128M` 左右。

## 3. 第二步：上传网站文件

1. 宝塔左侧【文件】→ 进入 `/www/wwwroot/`
2. 新建目录：`/www/wwwroot/wzbp`
3. 把项目**所有文件**上传进去（或用「远程下载」拉你的压缩包后解压）

上传完成后的目录应该是这样：

```
/www/wwwroot/wzbp/
├── index.html            ← 主入口
├── overlay.html          ← 采集画面页（MVP / 赛前）
├── package.json          ← 后端依赖声明
├── data/                 ← 133 位英雄数据（必须上传）
├── js/                   ← 前端脚本
├── styles/               ← 样式
├── vendor/               ← html2canvas（截图用，必须上传）
├── server/               ← Node 服务
└── docs/                 ← 本文档
```

> **两个别漏**：`data/`（英雄数据，缺了就空白）和 `vendor/`（截图库）。
> 上传后在文件管理器里确认这两个目录里有文件。

4. 设置属主（避免 Node 进程没权限读文件）：

```bash
chown -R www:www /www/wwwroot/wzbp
chmod -R 755 /www/wwwroot/wzbp
```

## 4. 第三步：建数据库

宝塔左侧【数据库】→【添加数据库】：

| 字段 | 填什么 |
| --- | --- |
| 数据库名 | `wzbp` |
| 用户名 | `wzbp` |
| 密码 | 点「随机」生成，**复制保存下来** |
| 权限 | **本地服务器**（不要选「所有人」） |
| 编码 | `utf8mb4` |

添加完成后，宝塔会列出一条记录。**把用户名和密码记下来，第五步要用。**

> 表结构不用手动建，Node 服务第一次启动时会自动建库建表。

## 5. 第四步：装依赖并试跑 Node 服务

宝塔左侧【终端】（或 SSH 登录），执行：

```bash
cd /www/wwwroot/wzbp

# 用宝塔的 Node（版本管理器里装的那个），一般路径如下
export PATH=/www/server/nodejs/v20.*/bin:$PATH     # 按实际版本调整，可用 ls /www/server/nodejs/ 查看
node -v                                            # 确认 >= 18

# 安装依赖（只装 mysql2 一个）
npm install --omit=dev
```

看到 `added 1 package` 之类就是成功。

### 配置数据库连接

服务通过**环境变量**读数据库配置。先手动试跑一次：

```bash
cd /www/wwwroot/wzbp
WZBP_DB_USER=wzbp \
WZBP_DB_PASSWORD='上一步复制的密码' \
WZBP_DB_NAME=wzbp \
WZBP_PORT=8787 \
node server/index.js
```

期望输出类似：

```
[wzbp] 端口 8787，监听 127.0.0.1
[wzbp] 数据库 wzbp@127.0.0.1:3306 连接正常，表结构已就绪
[wzbp] 英雄白名单加载成功：133 位
[wzbp] 服务已启动
```

看到「服务已启动」就说明后端通了，按 `Ctrl + C` 停掉，接下来交给宝塔常驻运行。

> **如果报数据库连接失败**：检查 ① MySQL 是否运行中；② 用户名密码是否复制错；
> ③ 数据库权限是否选了「本地服务器」。详见[第 12 节](#12-常见问题排查)。

> **关于 MariaDB**：宝塔的软件商店装的是 MySQL；如果你自己装的是 MariaDB（两者协议兼容，
> `mysql2` 都能连），有一处差异要知道：MariaDB 里 `JSON` 列实际是 `longtext` + `json_valid()`
> 校验（不是 MySQL 8 的原生 `json` 类型）。本服务读写两种形态都兼容，**功能完全等价，不用改**。

## 6. 第五步：用宝塔「Node 项目」常驻运行

宝塔左侧【网站】→ 顶部选【Node 项目】→【添加 Node 项目】：

| 字段 | 填什么 |
| --- | --- |
| 项目名称 | `wzbp` |
| 项目目录 | `/www/wwwroot/wzbp` |
| 启动文件 | `server/index.js` |
| Node 版本 | 你在第一步装的版本（如 20.x） |
| 项目端口 | `8787` |
| 运行用户 | `www` |
| 启动方式 | **npm** 或 **node** 都行；选 node 时启动参数填 `server/index.js` |
| 是否守护进程 | ✅ 勾上（宝塔会保活） |

### 加入环境变量（关键）

在同一个添加页面的【环境变量】区域，逐条添加：

| 变量名 | 值 |
| --- | --- |
| `WZBP_PORT` | `8787` |
| `WZBP_DB_HOST` | `127.0.0.1` |
| `WZBP_DB_PORT` | `3306` |
| `WZBP_DB_USER` | `wzbp` |
| `WZBP_DB_PASSWORD` | 你的数据库密码 |
| `WZBP_DB_NAME` | `wzbp` |

保存后，在 Node 项目列表里点【启动】，状态变成「运行中」。

> **注意**：Node 项目里配了「项目端口 8787」，宝塔可能会顺手给你加一条对外映射。
> 我们用 Nginx 反代，**不需要**把 8787 暴露到公网；如果宝塔提示要不要放行端口，
> 选择**不放行**（安全组里也不要开 8787）。

## 7. 第六步：建站点 + 反向代理（关键）

### 7.1 建站点

宝塔左侧【网站】→【添加站点】：

| 字段 | 填什么 |
| --- | --- |
| 域名 | 你的域名，如 `bp.example.com` |
| 根目录 | `/www/wwwroot/wzbp` |
| FTP | 不创建 |
| 数据库 | 不创建（第四步已建） |
| PHP 版本 | **纯静态** |

### 7.2 加反向代理

站点建好后，点该站点右侧【设置】→【反向代理】→【添加反向代理】：

| 字段 | 填什么 |
| --- | --- |
| 代理名称 | `wzbp-api` |
| 目标 URL | `http://127.0.0.1:8787` |
| 发送域名 | `$host` |

**然后必须改两个地方**（否则 SSE 实时推送会被 Nginx 缓冲，表现为「别人选完了我这边不动」）：

点【配置文件】，在 `location /api/` 那段里确认/改成：

```nginx
location /api/ {
    proxy_pass http://127.0.0.1:8787;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;

    # ↓↓↓ 让 SSE 实时推送生效的关键三行 ↓↓↓
    proxy_buffering off;
    proxy_cache off;
    proxy_set_header Connection '';
    proxy_read_timeout 3600s;
    chunked_transfer_encoding off;
}
```

> **为什么**：`/api/stream` 是 SSE 长连接。Nginx 默认会缓冲响应、
> 并在 60 秒后掐断空闲连接，导致前端收不到实时更新或频繁重连。
> 关掉缓冲 + 拉长超时即可。

保存后 Nginx 会自动 reload。

### 7.3 确认静态文件能访问

浏览器打开 `http://你的域名/`，应该能看到 BP 展示台界面。
如果 403/404，检查站点根目录是否指向 `/www/wwwroot/wzbp`、以及 `index.html` 是否在根目录。

## 8. 第七步：开 HTTPS

宝塔左侧【网站】→ 站点【设置】→【SSL】：

1. 选【Let's Encrypt】，勾选你的域名，点【申请】（免费，自动续期）
2. 申请成功后打开【强制 HTTPS】

> 用 HTTPS 还有个额外好处：浏览器对 `http` 页面的部分能力有限制，
> 而 `https` 下剪贴板、分享链接等体验更好。

## 9. 验证部署成功

按顺序验证这四项，全过就是部署完成：

### ① 后端健康检查

浏览器打开 `https://你的域名/api/health`，应返回：

```json
{ "ok": true, "version": "1.0.0", "time": "…", "db": true }
```

`db: true` 说明 MySQL 通；`false` 说明数据库没连上（回到[第 12 节](#12-常见问题排查)）。

### ② 首页进入联网模式

打开 `https://你的域名/`，顶栏应该出现「**房间**」入口（没有则说明前端没探测到 `/api/health`）。

### ③ 开一局试试

1. 点「房间」→ 填昵称 → 建房（赛制选**随机征召**，局数选 BO3）
2. 点「复制邀请链接」，用手机或另一台电脑打开
3. 对方点「坐下」加入战队（每队最多 5 人）
4. 双方轮流 ban/pick，看另一边是否**实时**跟着变

### ④ 还原一局

打完一局 → 打开「战绩」→ 点开刚打完的那局 → 拖动时间轴，
应该能看到每一步：**第几手、距上一手多久、谁选的、选了谁**。

## 10. 怎么用：队员加入队伍 → 管理员开局 → 自动计时

部署好之后的实际使用流程（**和你在线下开黑一样**）：

### ① 管理员建房（建房的人就是管理员）

打开你的域名 → 顶栏点「**房间**」→ 填房间名、选赛制、选 **BO几**、选 **每步限时**，
再填**管理员账号**和**管理员密码**，点「创建并进入」。

- **BO几** 就是这轮要打几局（BO3 = 打 3 局）
- **全局 BP** 会跨局记录：本方选过的英雄，本方后面几局不能再选
- 建完会把房间号（6 位）和邀请链接给你

### ② 队员「加入队伍」（这一步在开局之前）

把邀请链接发给队友（或让他们输房间号）→ 他们打开后：
点「房间」→ **在蓝方/红方点一个空位坐下** → 这就是「加入队伍」。

- 每队 5 个位置，两边共 10 人
- 会显示谁在线（绿点）
- **这时候还不能 ban/pick** —— 英雄区是锁住的，会写明「等待管理员开始 BP」

### ③ 管理员点「开始 BP」

管理员（建房时那个账号）在房间里能看到一个很大的「**开始 BP**」按钮，点它：

- 所有人的操作面板**同时解锁**
- 服务端确定本局 ban/pick 顺序（随机征召会在这里洗牌）
- **每步自动开始倒计时**，到 0 只提示超时、不会替你选

> 管理员不必占席位，可以是教练/裁判；也可以自己坐一个位置。

### ④ 按顺序 BP，全流程自动流转

- 顶部始终显示：**轮到谁**、**第几手/共几手**、**还剩多少秒**（最后 10 秒变红）
- 轮到谁谁高亮；不是你的回合会写明原因（「现在还轮不到你（你是蓝方），等红方先操作」）
- 每落一手，倒计时**自动重置**为下一步的完整秒数
- 轮到谁、该 ban 还是 pick，都由服务端权威判定，别人乱点会被拒并给出中文原因

### ⑤ 一局打完 → 下一局 → 看回放

- 管理员在「系列赛控制台」里选胜负、点「**下一局**」（全局 BP 的记录会跨局累计）
- 打满 BO几 局后整场结束
- 点顶栏「**战绩**」→ 打开任意一局 → **拖时间轴**可以跳到任意第 N 手，
  每一步都显示「第几手 / 距上一手多久 / 谁选的 / 选了谁」

### 管理员的额外能力

暂停/继续计时 · 撤销上一手 · 换下一局 · 结束系列 · 重洗随机顺序（仅本局未落子时）。
这些**只有管理员能操作**，避免大家同时点造成混乱。

### 空 BAN（禁用阶段可以不下手）

轮到禁用时不想 ban 英雄，点控制台步骤提示条上的「**空 BAN**」按钮即可（不用先选英雄）。
空 ban 占一个 ban 位但不消耗英雄，展示板上会显示成虚线框的「空BAN」。
**只有禁用阶段能空**，选人必须真选一个。

### 采集画面有哪几个

直播时在 OBS 里每个画面加一个「窗口采集」：

| 画面 | 地址 | 放什么 |
| --- | --- | --- |
| BP 展示板 | `index.html?wzrole=display` | ban/pick 位、中央原画、**战队名 + 头像** |
| MVP 卡 | `overlay.html?mode=mvp` | 选手 ID、英雄原画、战绩数据 |
| 赛前面板 | `overlay.html?mode=pre` | 双方队名/情报、五人位置、交锋史 |
| **战绩面板** | `overlay.html?mode=record` | **双方队名+头像、大比分、每局胜负、冠军** |

控制窗的「赛事面板」里对应 **MVP 卡 / 赛前面板 / 战绩面板** 三个页签。

- **战队名与头像**：控制台顶部每组有「头像圆钮 + 队名输入框」，点圆钮上传图片（自动缩小），
  改完展示板与所有采集画面立刻跟着变。
- **战绩**：在「战绩面板」页签里逐局点「蓝胜 / 红胜」，大比分和冠军**自动算**；
  点「按赛制对齐局数」可按 BO 数生成局数（BO5 → 5 局）。

## 11. 日常运维：备份、更新、看日志

### 看日志

宝塔【网站】→【Node 项目】→ 你的项目 →【日志】，能看到服务输出。
Nginx 日志在【网站】→ 站点 →【日志】。

### 备份数据

两种都要备：

1. **数据库**：宝塔【数据库】→【备份】→ 建议开「自动备份」，保留 7 天。
   也可以导出：`mysqldump -u wzbp -p wzbp > wzbp_$(date +%F).sql`
2. **网站文件**：宝塔【文件】里把 `/www/wwwroot/wzbp` 打包下载，
   或【计划任务】里加一条「备份网站」。

### 更新代码

```bash
cd /www/wwwroot/wzbp
cp -r data data.bak            # 保险起见先备份数据目录
# 上传新文件覆盖（不要删 node_modules）
npm install --omit=dev         # 如果 package.json 有变化
```
然后在宝塔 Node 项目里点【重启】。

### 重启服务

宝塔【Node 项目】→ 点【重启】。命令行方式：
`bt` 菜单里重启，或直接 `pkill -f 'server/index.js'` 后由守护进程自动拉起。

## 12. 常见问题排查

### Q1 `/api/health` 返回 `db: false` 或 502

**按这个顺序查**：

```bash
# 1. MySQL 在跑吗
systemctl status mysqld        # 或 service mysql status

# 2. 用命令行连一下（换成你的密码）
mysql -h 127.0.0.1 -u wzbp -p -e "use wzbp; show tables;"

# 3. Node 服务在跑吗
ps aux | grep 'server/index.js'

# 4. 端口通不通
curl http://127.0.0.1:8787/api/health
```

- 第 2 步连不上 → 数据库权限没选「本地服务器」，或密码错 →
  宝塔【数据库】→ 该库【权限】里改成「本地服务器」，或直接改密码。
- 第 4 步连不上但服务在跑 → 环境变量没配全，去【Node 项目】→【环境变量】补；
  改完必须**重启项目**才生效。

### Q2 页面能打开，但没有「房间」入口

说明前端没探测到 `/api/health`。检查：

```bash
curl https://你的域名/api/health
```

- 404 → 反向代理没配对，或代理路径不是 `/api/`
- 502 → Node 服务没运行（回到 Q1）
- 返回正常但页面还是没入口 → 浏览器强刷（`Ctrl+F5`）清缓存

### Q3 建房后别人看不到更新 / 一直转圈

**九成是 Nginx 缓冲了 SSE**。回到[第 7.2 节](#72-加反向代理)，
确认 `location /api/` 里有 `proxy_buffering off;` 和 `proxy_read_timeout 3600s;`。

改完执行 `nginx -t && nginx -s reload`。

### Q4 加入房间提示「队伍已满」

每队最多 5 人（对应一局 5 个位置）。换个队，或让房主清理掉不用的席位。

### Q5 上传后英雄列表是空的

`data/` 目录没传全。确认 `data/heroes.js` 和 `data/skills.js` 存在且非空。

### Q6 截图功能报错

`vendor/html2canvas.min.js` 没上传。这个文件是本地依赖，缺了截图按钮不可用。

### Q7 内存被吃满 / 服务被系统杀掉

1G 内存的机器上 MySQL 8 比较吃紧。把 `innodb_buffer_pool_size` 调到 `128M`，
或在宝塔里给 MySQL 换个更省内存的配置。1 核 1G 跑这个站是够的。

## 13. 安全建议

1. **不要放行 8787 端口**。Node 只监听 `127.0.0.1`，外网一律走 Nginx。
2. **数据库权限选「本地服务器」**，不要开「所有人」。
3. **开 HTTPS 并强制跳转**。
4. **定期备份**数据库与网站目录（第 10 节）。
5. 如果被刷接口，可在 Nginx 里对 `/api/` 限速：

```nginx
location /api/ {
    limit_req zone=one burst=20 nodelay;
    # …其余同上
}
```
（需先在 `http {}` 段定义 `limit_req_zone $binary_remote_addr zone=one:10m rate=10r/s;`）

6. 房间号是 6 位随机码，**不要**用房间号当机密；不想被陌生人进就私下发链接。
